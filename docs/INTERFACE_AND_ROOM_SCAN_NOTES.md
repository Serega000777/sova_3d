# Editor and room scan implementation notes

## Pro editor

The simple editor keeps the model and a short left tool rail in focus. Pro exposes a searchable catalog of **working** operations, grouped into shapes, exact geometry, transforms, inspection and output. Choosing an action opens its actual parameter panel. This follows the discoverable workspace/tool grouping used by [Autodesk Fusion](https://help.autodesk.com/cloudhelp/ENU/Fusion-GetStarted/files/GS-WORKSPACES.htm), the contextual command access in [3ds Max](https://help.autodesk.com/cloudhelp/2027/ENU/3dsMax-Basics/files/3ds_max_interface_overview/GUID-3A803F43-6F87-40FB-97CA-33844078AF9A.html), and the expanded tools in [SketchUp for Web](https://help.sketchup.com/en/sketchup-web/sketchup-web-expanded-toolbar). [Nomad Sculpt](https://nomadsculpt.com/manual/gettingstarted) is the reference for a persistent, scrollable tool rail on smaller screens.

The catalog is an entry point for existing geometry operations. A future developer tier should add capabilities only with real kernel support and tested controls; a long menu of nonworking commands would mislead users.

## iPhone and iPad room scanning

The mobile route offers object, room and home choices. Object always records RGB photo frames. Room and home offer a choice between RGB photos (size is a user estimate) and, when the platform reports LiDAR support, RoomPlan — real measured geometry. One home session still means one room either way; T-197 (multi-room merge) is not implemented.

**T-196 (25.09.2026), implemented but not device-validated.** `apps/mobile/modules/expo-room-plan` is a local Expo module (Expo Modules API, Swift) hosting Apple's own [`RoomCaptureView`](https://developer.apple.com/documentation/roomplan/roomcaptureview) — it adds no AR rendering of its own, only the plumbing from a declarative `capturing` prop to `RoomCaptureSession`'s lifecycle and from its delegate callbacks to JS events (`onRoomUpdate` with live wall/opening/object counts, `onCaptureFinish` with a USDZ path, `onCaptureError`). `src/capabilities.ts`'s `depthScan` defers entirely to the module's `isSupported()` (`RoomCaptureSession.isSupported`, `#available(iOS 16.0, *)`-gated) — it is never hardcoded true and is always false in Expo Go, which cannot load native modules. On capture finish, `app/scan/index.tsx` uploads the exported USDZ as a `mode: "scanner"` fragment (`src/scan.ts::uploadRoomCapture`); it goes through the same `fusion` reconstruction provider a dedicated scanner's fragments use (`worker/reconstruction.py`), which now also reads `.usdz` fragments directly (`_load_fragment`, converting the stage's `metersPerUnit` to millimetres — RoomPlan exports in metres).

**What this does not prove**: this machine has no Xcode/macOS, so the Swift has never been compiled — only written against documented RoomPlan/Expo Modules API and checked by reading, not by a compiler or a device. Treat `CapturedRoom.USDExportOptions.mesh` and the exact `RoomCaptureSessionDelegate`/`RoomCaptureViewDelegate` signatures in `ios/ExpoRoomPlanView.swift` as needing a real build to confirm. Building needs `eas build --profile development --platform ios` (or local Xcode) and an Apple Developer account — not Expo Go, and not this dev environment.

Multiroom capture (T-197) should retain the AR session, finish each room separately and combine the resulting rooms with [StructureBuilder](https://developer.apple.com/documentation/roomplan/scanning-the-rooms-of-a-single-structure). The merged structure is the source for a home model; derive and validate the editable 2D plan from its measured walls, openings and room coordinates. Not started — do this only after T-196 is confirmed working on a physical device, so it builds on a proven capture path rather than compounding unverified native code.

[Polycam Space Mode](https://learn.poly.cam/hc/en-us/articles/36655587097620-How-to-Use-Space-Mode-LiDAR-Devices) demonstrates a room-scan flow with a 3D mesh and floor plans. [Planner 5D](https://support.planner5d.com/en/articles/5897614-scan-your-room-ios) demonstrates a guided room capture. These are workflow references, not proof that our current RGB implementation offers equivalent measurements.

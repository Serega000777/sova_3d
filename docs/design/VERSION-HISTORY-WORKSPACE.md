# Сцена и история версий — единое рабочее пространство пункта 30

Дата: 13.10.2026. Статус: bounded web increment реализован.

## Цель

Свести в одном инструменте Web Studio то, что раньше было разделено между «Сценой» и
«Версиями»: дерево объектов выбранной immutable-версии, её thumbnail, автор, дата, размер
привязанных файлов и человеческий комментарий. Выбор строки истории синхронно переключает
viewport и дерево сцены, поэтому пользователь не сравнивает метаданные одной версии с геометрией
другой.

## Серверная модель

- `GET /projects/{project_id}/version-history` возвращает обычный `VersionOut` плюс display name
  автора, комментарий, revision комментария и сумму размеров уникальных attached assets;
- один asset, прикреплённый к нескольким ролям, учитывается в размере один раз;
- комментарий не записывается в `project_versions`: finalized-версия и её provenance остаются
  неизменяемыми;
- отдельная таблица `version_comments` хранит один комментарий до 2000 символов на версию,
  `revision`, автора и время последнего обновления;
- `PUT /versions/{version_id}/comment` требует editor role и точный `base_revision`. Строка версии
  блокируется до CAS-проверки, поэтому конкурентные сохранения сериализуются, а stale-клиент
  получает `409` вместо тихой потери текста;
- foreign workspace получает `404` и для ленты, и для комментария; viewer может читать историю,
  но не менять комментарий.
- полный owner handoff проекта копирует комментарии на новые version ids вместе с immutable graph,
  поэтому история не теряется при уже реализованной передаче проекта.

## Клиент

Инструмент «Версии» использует responsive две колонки: дерево сцены слева, история справа. На
узком экране колонки складываются вертикально. Карточка версии показывает canonical thumbnail
выбранного ракурса, название, автора, локализованную дату, суммарный размер и сохранённый
комментарий. Выбранный комментарий редактируется отдельно с явным сохранением и счётчиком длины.
Restore по-прежнему создаёт новую версию и ничего не удаляет.

## Граница

- комментарий один на версию, без threaded discussion, упоминаний и вложений;
- размер — сумма хранимых attached assets, а не оценка RAM/GPU или объёма всей CAS-базы;
- display name берётся из профиля; если он отсутствует, UI показывает безопасный короткий id;
- физическая browser/device visual acceptance не выполнялась; подтверждены API, generated contract,
  TypeScript и production build.

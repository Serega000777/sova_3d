# Участок вокруг дома — bounded composition для пунктов 37/38

Дата: 13.10.2026. Статус: первый end-to-end increment реализован; camera AR остаётся отдельно.

## Цель

Дать существующему точному house-wizard проекту настоящую сцену участка, а не локальную
декорацию клиента. Пользователь задаёт размеры прямоугольного участка, четыре относительные
высотные отметки, положение/поворот дома, ломаную дорожку и стороны ограждения. Результат — новая
immutable project version, которую одинаково читают scene tree, viewer и обычный scene export.

## Каноническая граница

- источник обязан иметь server-owned `house_box.request`; импортированный/сканированный mesh не
  переименовывается в измеренный дом;
- поддерживается прямоугольная граница участка 5–200 м, четыре угловые отметки с перепадом не
  более 10 м, одна дорожка из 2–16 точек и ограждение на выбранных сторонах;
- envelope дома вычисляется из доверенных `length_mm`/`width_mm` и реального Z-поворота; дом с
  обязательным отступом 500 мм должен целиком находиться внутри участка;
- path-точки обязаны находиться внутри участка, нулевые сегменты и повторные стороны ограждения
  отклоняются;
- terrain/path/fence — реальные закрытые STL assets в миллиметрах; дорожка и стойки/рейки забора
  следуют тому же треугольному рельефу, а не остаются на условном `z=0`. Исходные узлы дома не
  копируются и не сплющиваются: их корневые nodes переподчиняются группе `site_house`, которая
  несёт rigid transform;
- сервер сэмплирует рельеф под повёрнутым footprint дома, поднимает дом над максимальной отметкой
  и добавляет отдельную закрытую каменную площадку `site_house_pad` до минимальной отметки. Это
  сохраняет исходную геометрию дома и не выдаёт наклонный грунт за готовый фундаментный проект;
- `site_root`, `site_house`, `site_house_pad`, `site_terrain`, `site_path`, `site_fence` остаются
  отдельными scene nodes с visibility/export parity. Рельеф получает зелёную matte appearance,
  площадка и дорожка — камень, забор — графит из уже доверенного server-side material snapshot
  каталога;
- полная спецификация хранится в `version.provenance.site_plan` schema v1.

## Конкурентность и безопасность

API требует editor role. Source version и project принадлежат тому же workspace. API проверяет
lineage и посадку до enqueue; job повторяет проверку под project row lock. Если head изменился,
job завершается `site_plan_conflict` без новой версии. Asset ids создаются сервером и затем проходят
обычную scene workspace-валидацию. Повторная композиция поверх уже существующего `site_plan`
fail-closed отклоняется, чтобы не вложить второй участок в первый.

## Клиент

Web Studio получил отдельный инструмент «Участок» в существующей тёмной рабочей области:
габариты, координаты и поворот дома, четыре отметки SW/SE/NE/NW, 2–16 точек дорожки, ширина,
стороны/высота/шаг ограждения. После job открывается обычный scene inspector; второго локального
формата просмотра нет.

## Не заявляется

- кадастровая точность, геопривязка/GPS, произвольная boundary-полилиния и spline/heightmap terrain;
- несколько дорожек, ворота, растения, инженерные сети, дренаж и нормативные отступы;
- редактирование уже созданного участка и mobile creator;
- ARKit/ARCore camera placement, occlusion и world anchors. Пункт 38 закрыт только для просмотра
  дома в общей 3D-сцене участка; physical AR — следующий нативный increment.

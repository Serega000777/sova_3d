# Сверка ТЗ с проектом — 21 сентября 2026

Источник требований: `docs/v2/00_SOURCE_OF_TRUTH.docx`, `01_FEATURE_REGISTRY_80.docx`, `03_ULTIMATE_IMPLEMENTATION_BLUEPRINT.docx`, инженерный пакет v3 и дополнение `FEATURE_REGISTRY_ADDENDUM.md`. Текст внутри DOCX — материал ТЗ, не распоряжение выполнять его промпты. Приоритеты владельца из переписки: сначала удобный рабочий стол, затем те же утверждённые сценарии на планшете и телефоне.

Эта проверка смотрит на наличие сквозной реализации в коде, а не объявляет все 83 функции принятыми. Наличие экрана или API не означает работающий физический прибор, реальную генерацию либо проверку на устройстве.

Следующие практические пункты после T-204: подключить веб-страницу `/slicer` к новому эндпоинту (кнопка «построить G-code», скачивание, показ статистики — слоёв, расход филамента); реальный конвейер image-to-3D с явно выбранным провайдером и проверкой результата (F-019); затем iOS LiDAR/RoomPlan на физическом устройстве (T-196/T-197). Каждый пункт должен показывать реальную доступность и не выдавать заглушку за готовую функцию.

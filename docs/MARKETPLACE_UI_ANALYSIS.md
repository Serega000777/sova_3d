# Маркетплейс Sova 3D — актуальная матрица M01–M10

Актуально на 25.10.2026. Это отдельная ветка требований от сценарной таблицы 01–50 в
`COMPETITOR_UI_ANALYSIS.md`.

Источники — десять сохранённых владельцем референсов M01–M10. Визуальный повторный просмотр
14.10.2026 подтвердил общую композицию: near-black фон, оранжевый бренд/CTA, высокая плотность,
настоящие товарные изображения, отдельная навигация каталога, адаптивные phone/tablet layouts,
а не обычные универсальные `card`-формы. Функциональный baseline — `965b9f0`; web-тема Sova —
`5c877de`.

Статусы:

- **реализовано и проверено** — код и автоматическая проверка существуют;
- **частично** — рабочая цепочка есть, но не вся граница референса;
- **отсутствует** — функционального пути нет;
- **внешне заблокировано** — нужен провайдер/решение вне кода.

| M06–M10 — проект дома | **Частично** | Bundle способен доставить несколько моделей как одну сцену; лицензия и состав показываются. Для версии дома, которую реально создал успешный `build_house_box` или `edit_facade` job, API выводит форму, длину, ширину, этажность и gross floor area. Площадь rectangle/L/T считается по восстановленному валидированному полигону этажа, а не по завышающему bounding rectangle. Typed auto-layout child теперь наследует эти house facts только по точной parent-chain; имена, типы, этажи и фактические площади комнат появляются в карточке/product page лишь когда валидированный `FloorPlan`, `floor_plan_layout` и включённая immutable-операция `update_floor_plan` согласованы. Технические `Footprint`/`House`, untyped layout и подложенный plan JSON комнатами не считаются (`9c3108b`). Product page показывает доказанные этажи отдельными вкладками в read-only SVG: стены, проёмы, лестницы и только подтверждённые typed-комнаты восстанавливаются из валидированного job/immutable history (`428da53`). Для версии, произведённой успешным `edit_facade`, там же показывается read-only спецификация крыши, толщины стен и адресных проёмов с этажом/стороной/размерами. Для такого доказанного дома доступны два настоящих документа: многостраничный vector PDF с обложкой/фасадной ведомостью/листами этажей и детерминированный XLSX с листами Summary, Floors, Rooms и, для exact-фасада, Facade. Оба маршрута требуют авторизацию и восстанавливают данные из валидированного immutable evidence; подложенная provenance получает 422 вместо документа. После покупки buyer-only маршрут также собирает настоящий `.sova` ZIP-контейнер: versioned manifest, проект/immutable provenance/operation stack и только фактически доставленные source/model/export файлы из workspace покупателя. Каждый бинарный файл проверяется по сохранённым SHA-256 и размеру до выдачи; чужой заказ скрывается как 404, повреждённое хранилище даёт 422. | DWG отсутствует; `.sova` описывает редактируемую каноническую копию Sova 3D, а PDF/XLSX остаются техническим паспортом и ведомостью, не рабочей документацией для строительства. Визуальная browser/device-приёмка планов и документов открыта. |
| M06–M10 — композиция двора | **Частично** | Bundle и multi-node scene технически поддерживают несколько объектов. Версия, созданная успешным canonical `compose_site_plan` job, получает в marketplace доказуемые размеры участка, перепад четырёх углов, положение/поворот и размеры дома, траекторию/ширину дорожки, стороны ограждения и список фактически сохранённых scene-объектов. Product page строит из этих данных read-only SVG composition view; подложенная `site_plan` provenance без точного succeeded job и прикреплённых scene assets получает пустой результат. До покупки можно выбрать свой проект участка: API сравнивает длину и ширину только двух job-proven head-композиций, отдельно сообщает прямое размещение, размещение с поворотом на 90°, несовместимость или отсутствие доказательств; площадь сама по себе не считается достаточной. Когда контуры совпадают точно, API перебирает только геометрически допустимые повороты 0/90/180/270°, совмещает юго-западный угол и возвращает измеренную разницу относительной высоты всех четырёх углов плюс максимум. ## Почему dev-сервер выглядел пустым и как это устранено

Проверка 14.10.2026 установила три независимые причины:

1. На 14.10 dev PostgreSQL содержал 1 пользователя и 1 workspace, но **0 проектов, 0 версий,
   0 опубликованных листингов и 0 creator profiles**. Теперь команда
   `python -m app.cli seed-marketplace-showcase` явно создаёт обычные доменные записи и
   content-addressed assets; она запрещена в production и не вызывается при чтении каталога.
2. API-контейнер был собран 09.10.2026 и не содержал поздние маршруты cart, room-shell,
   version-history, interior-material и site-plan. Контейнер обновлён до текущего `main`, база
   мигрирована с `0030` до `0032`; runtime boundary исправлена `9cf69e4`.
3. Web rebrand существовал только как design doc. Mobile был orange, web оставался blue. Первый
   web-инкремент теперь реализован `5c877de`, но это глобальная visual system и onboarding, а не
   полная перестройка marketplace layouts M01–M10.

## Отдельно: визуальная паритетность

Совпадение функций не равно совпадению макетов. После `5c877de` подтверждены кодом:

- Sova 3D wordmark и собственный SVG-mark;
- near-black/orange tokens, CTA и состояния выбора;
- тёпло-белый материал модели с orange hover/selection;
- новый responsive onboarding идея→точная правка→печать;
- прежние Yandex/VK brand colors сохранены.

Marketplace shell больше не является одной универсальной сеткой: добавлены image-first hero,
editorial lanes, desktop category rail и mobile bottom navigation/filter panel. Но полноценного
category tree и rich product/gallery composition референсов ещё нет. Автоматический browser
screenshot gate не выполнен: browser host не запускает Chromium из-за отсутствующих системных
`libnspr4.so`, NSS/ATK-библиотек. TypeScript, web unit и production build проверены;
визуальная parity должна считаться
**неподтверждённой**, пока реальный browser/device не отрисует phone/tablet/desktop breakpoints.

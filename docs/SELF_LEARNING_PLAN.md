# Самообучение моделей — что есть, чего нет, как сделать честно

Запрос: «чтобы наша модель сама по себе обучалась» (как переключатель «Обучить AI» у KIRI Engine).

## Что есть сейчас — честно

**Ничего не обучается.** Платформа не дообучает и не настраивает ни одну модель на данных
пользователей. AI-планировщик — внешняя модель (Anthropic) за адаптером; реконструкция
(Shap-E, фузия кадров) использует готовые веса.

Зато платформа уже сохраняет сигналы качества, на которых можно строить обучение:

| Сигнал | Где лежит | Что говорит о качестве |
| --- | --- | --- |
| Запрос и его итог | `ai_requests` (prompt, status, safety_state, output_plan, tokens, cost) | выполнен ли план, отклонён ли |
| Ошибки плана | `ai_requests.plan_errors` | чем именно план не прошёл валидацию |
| Цепочка версий | `project_versions` + provenance | принял ли человек результат, к какой версии вернулся |
| Откаты | job `rollback` (T-123) | человек отменил результат — сильный негативный сигнал |
| Ручные правки после AI | `operations` (ai_request_id у правок) | как человек исправил то, что предложил AI |
| Провалы обработки | `jobs.error` (code, details) | где пайплайн не справился (например `below_tolerance`, `stale_selection`) |

## Чего нельзя делать

- Включать обучение на данных пользователей по умолчанию. У KIRI переключатель «Обучить AI»
  стоит включённым; у нас он должен быть **выключен** до явного согласия. В реестре создания
  (`packages/contracts/src/create-scenarios.ts`) `allowTraining` и `publicVisibility` по умолчанию
  `false`, это закреплено тестом.
- Обещать в интерфейсе «модель учится», пока нет конвейера: переключатель без потребителя —
  обман. Поэтому в экранах создания переключателя пока нет.

## Как сделать по-настоящему (по шагам)

1. **Согласие.** Флаг `training_consent` на проекте (и на скане): выключен по умолчанию, меняется
   только владельцем, версионируется (когда дал/отозвал). Отзыв исключает данные из будущих выгрузок.
2. **Обратная связь.** Явные кнопки «хорошо / плохо / исправил» у каждого результата AI и
   реконструкции + причина из короткого списка. Неявные сигналы (откат, правка после AI) уже есть.
3. **Датасет.** Периодическая выгрузка только согласованных данных: запрос → план → итог → оценка,
   без персональных данных, с хэшами вместо идентификаторов; формат и версия схемы фиксируются.
4. **Что именно улучшать** (по возрастанию риска):
   - подсказки и примеры в промпте планировщика из удачных пар (без обучения весов);
   - ранжирование вариантов эскизов по сигналам принятия;
   - дообучение небольших моделей (например классификатор «печатается / нет») на размеченных данных;
   - дообучение самой генерации — только после оценки стоимости и юридической проверки.
5. **Оценка перед выкладкой.** Фиксированный набор регрессионных запросов (он уже есть:
   `services/api/tests/prompt_corpus.json`) + сравнение «до/после» по доле принятых результатов.
   Модель не выкатывается, если метрики хуже.
6. **Приватность и право.** Политика хранения, возможность удалить данные и отозвать согласие,
   отдельное согласие на публичную выдачу. Работа с лицензиями моделей из маркетплейса — по их
   лицензии (`license_id`), а не по умолчанию.

## Что сделать первым

Шаг 1 (флаг согласия + экран настроек) и шаг 2 (кнопки оценки) — небольшие, не требуют ML и сразу
дают данные. Остальное имеет смысл только когда накопится достаточно согласованных примеров.

Статус: **не начато** (в коде только безопасные значения по умолчанию в реестре создания).
